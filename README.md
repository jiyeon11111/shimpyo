# 쉼표

폭염 시간에 쉰 배달 라이더에게 쉰 만큼 소득을 보전하는 앱과 판정 엔진.

## 지급 기준 (팀 확정안, 2026-11-09)

쉬기 시작하는 순간 세 가지가 모두 맞으면 지급 대상이다.
1. **평소 일하던 시간 (노동 확인):** 하루를 다섯 시간대(06-09, 09-12, 12-15, 15-18, 18-22)로 나눈다. 쉼을 시작한 시각이 속한 시간대에 최근 28일 중 12일 이상 일했다. 22~06시는 지급 대상이 아니다.
2. **뜨거운 동:** 쉬기 직전 1시간 동안 가장 오래 달린 행정동의 체감온도가 32도 이상이다(시간대 제한 없음). 온도는 행정동 체감온도 모델 값이고, 32도는 모델 값 전용 판정선(33도 − 모델 불확도)이다. 센서 실측끼리 판정할 때는 33도를 쓴다. 달린 분은 이동 1(수락 → 음식점 도착)은 출발동·음식점동에, 이동 2(픽업 → 배달 완료)는 음식점동·고객동에 반씩 나눠 더한다.
3. **실제 노출:** 최근 2시간 실제 배달 이동(콜 수락 → 음식점 → 고객)이 누적 60분 이상이다. 콜을 켠 채 기다린 시간은 세지 않고, 20분 넘는 공백이 있으면 누적이 0으로 돌아간다.

쉼 버튼을 누르면 콜이 꺼지고, **20분 이상** 쉬어야 인정한다. 금액은 **min(평소 시간당 수입, 2만 원) × min(쉰 분, 30) ÷ 60**이다. 평소 시간당 수입은 최근 4주 같은 요일·같은 1시간의 배달료 합을 그 시간에 일한 주만 평균한 값이다. 체감온도가 더 높다고 더 주지 않는다. 상한은 **한 번 최대 1만 원, 하루 4번**이다.
32도, 60분, 28일 중 12일, 1만 원은 확정안이고, 30분과 4번은 초안이라 분석 3·4로 확정한다(`engine/rules.py`, `engine/payout.py`의 숫자만 고치면 된다). 직사광선 아래 대기는 노출로 세지 못하는 한계가 있다.

## 바로 실행 (VS Code)

```
python -m venv .venv
.venv\Scripts\activate          # macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # Windows: copy .env.example .env
uvicorn backend.main:app --reload --port 8000
```

브라우저에서 http://localhost:8000 을 열면 앱이 뜬다. API 문서는 http://localhost:8000/docs.
VS Code에서는 실행 및 디버그(Ctrl+Shift+D)에서 "쉼표 서버 (FastAPI)"를 고르고 F5.

설치 없이 먼저 보고 싶으면 `python -m backend.serve_stdlib` (파이썬 기본 라이브러리만 쓰는 같은 API 서버, 8000번 포트).

## API

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/config` | 시연 모드 여부, 기준 숫자(32도, 60분, 20분, 30분, 1만 원, 4번, 12일/28일, 시간대) |
| GET | `/api/now?lat&lon` | 가장 오래 달린 동(`judge_dong`)의 모델 체감온도, 단계, 지금 쉬면 받는지(`pay_now`)와 안 되는 이유(`reasons`), 배달 이동 분, 평소 시간당 수입, 가장 가까운 쉼터 |
| POST | `/api/rest/start` | 쉬기 시작 `{rider_id, lat, lon, place: auto\|shelter\|street}`. 이 순간 판정하고 근거를 기록 |
| GET | `/api/rest/current` | 쉬는 중이면 지금까지 잠정 적립과 안 되는 이유 |
| POST | `/api/rest/stop` | 쉼 종료, 정산 후 저장 |
| GET | `/api/history` | 오늘 기록, 오늘 받은 돈·남은 횟수, 이번 달 합계, 최근 7일 |
| GET | `/api/shelters?lat&lon&kind=rider` | 가까운 쉼터 |
| GET | `/api/report?lat&lon` | 지자체·보험사용: 관악구 21개 동 체감온도·보전 시간·지급액·못 쉰 위험 시간, 2026 여름 합계 |
| GET | `/api/dongs` | 관악구 행정동 경계와 중심 좌표 (지도용) |
| POST | `/api/demo/reset` | 시연 날짜에 눌러 만든 기록 지우기 |

시연 모드에서는 모든 요청에 `at=HH:MM`을 붙여 시각을 바꿀 수 있다.

## 시연 모드와 실제 모드

- **시연 모드 (`SHIMPYO_DEMO=1`, 기본)**: 날짜를 2026-08-03, 위치를 관악구청(청룡동)으로 고정한다. 체감온도는 관악구 행정동 모델 값이고, 민수는 가상 라이더 R0297의 콜 기록을 쓴다. 지역 현황은 가상 라이더 1,000명을 미리 집계한 결과(`python -m analysis.gwanak_summer`)를 읽는다. 쉼터 5곳과 지난 기록 4건도 가상이다. 인터넷 없이 발표장에서 동작한다. 화면 위 시연 막대로 시각을 옮기거나 재생한다. **이 값들은 모두 지어낸 것이다. 결과로 인용하지 않는다.**
- **실제 모드 (`SHIMPYO_DEMO=0`)**: 공공데이터포털에서 "기상청_단기예보 조회서비스" 인증키를 받아 `.env`의 `KMA_SERVICE_KEY`에 넣는다. 브라우저 위치를 쓰고, 기온·습도 예보로 체감온도를 계산한다 (30분 캐시).
- 실제 쉼터 목록: 행정안전부 무더위쉼터와 지자체 이동노동자 쉼터를 `data/raw/shelters.csv`로 넣는다 (열: 쉼터명, 구분, 주소, 위도, 경도, 운영시간, 비고).
- 동 이름 표시: 기상청 격자-행정구역 표(`data/raw/kma_grid.csv`)를 넣으면 격자 대신 시군구·읍면동이 나온다.

## MVP에서 가정한 것

- 운행 기록(자격·노출·평소 수입)은 플랫폼 협약 후 `backend/riders.py`에 붙인다. 그 전까지 실제 모드는 적립 여부를 판정하지 않고 "운행 기록 연결 전"으로 보여준다.
- 라이더는 1명(민수, id 1)으로 고정. 로그인 없음.
- 대시보드의 가상 라이더 1,000명은 쉼 버튼 기록이 없어서, 팀 분석 4와 같이 배달을 마칠 때마다 자격이 되면 절반(기본값)이 30분 쉰다고 가정하고 앱과 같은 엔진으로 판정·정산했다.
- 쉼터 밖 쉼은 위치가 멈춰 있는지 확인하는 단계가 들어갈 자리만 있고, 시연 모드에서는 바로 인정한다.
